# Off the PS1

Status: the project's main line of work from 2026-11-08 (the owner: "get off the PS1"; "we should fix root
causes"). Map of what is meant: [PS1_Ties.md](../PS1_Ties.md); T numbers below are its ties.

## Why

The game is a PS1 program running on a fake PS1 with a modern engine around it. That is the root of the jank:
everything stalls together because everything runs inside `VSync` on one thread; the small graphical bugs come
from rebuilding a modern picture out of PS1 packets, VRAM and 4:3 assumptions; motion is uneven because the
world updates at 30 and only native 3D is interpolated. Work on top of that core treats symptoms.

## Done means

Measured, not judged:

- `ps1_address_lint.py`: 0 PS1 addresses, scratchpad addresses, guest pointers and addresses as integers.
- No program code or tables read from the disc: assets only.
- No GPU packets, ordering tables or VRAM array; the game submits frames as data.
- No GTE state machine or PS1 sound registers in game logic.
- Logic, rendering, audio and input run independently: a stall in one does not stall the others, and the display
  rate is free of the logic's rate.

The game must still look and play like Vagrant Story: "looks classic, feels modern".

## Dependency order

A topological sort of the ties in [PS1_Ties.md](../PS1_Ties.md), by level: everything in a level can run at once
once the levels above it have what it needs. The map's own "depends on" column had to be corrected in three
places:

- T9 and T10 depended on each other. Overlays go first: their code is already linked natively, so they can
  become modules with explicit reset and their tables our own data while disc reads still exist. Disc reads then
  follow.
- T10 and T12 depended on each other. T12 is split: fixed RAM can only go after overlays stop assuming slot
  addresses, so T10 comes first and needs only T13 and T15.
- T4 "depends on" T13 and T14 only because packets are built through them. A screen that moves to typed draw items
  drops those uses, so T4 runs beside T13. Converting packet code's pointers first would be wasted work:
  ordering-table links and packet structs are left to T4 and never swept.

```
Level 0  (nothing first)      cull battle's C | T13a byte offsets to named fields | T7 GTE values
                              T3 scanline clock | T20a analog and rumble | T22 native save file
Level 1  (needs cull, T13a)   T13b pointer sweep and wider pointers | T4 frames as data (long; runs through L3)
Level 2  (needs T13b)         T14 scratchpad | T15 globals at PS1 addresses, raw memory in Zig
         (needs T4 started)   T8 2D, text and effects, screen by screen
Level 3  (needs T15)          T10 overlays to modules -> T9 disc reads by asset -> T19 XA, T21 movies, T18a samples
         (needs T4, T8)       T5 VRAM | T6 display area and 4:3 (also needs T7)
Level 4  (needs T10, T14)     T12 fixed RAM and heap -> T17 save states, rewind, RPC
         (needs T15)          T11 build ties to the original binaries
Level 5  (needs T4, T7, T13)  T1 loop and thread, T23 -> T2 display rate, T18b sound off the game thread,
                              T20b input latency
Last                          T16 what remains of the SDK and BIOS layer, then src/ and the setup that reads it
```

The critical path, the longest chain, is cull -> T13a -> T13b -> T4 and T8 -> T1 -> T2. T1 is what the player feels
most and it comes late because it needs frames to be data.

The game stays playable and on main throughout: each step merges on its own.

## Rules

- This comes first. New features, polish and bug hunts on the old paths wait, unless the game is unplayable.
- Nothing that patches a PS1 tie gets built when the tie itself is scheduled for removal.
- When a piece of the old path stops being used, it is deleted in the same work.
- Checks stay within the quick lane. The lint and the golden frames are the meters. Golden frames may be
  re-recorded only for a change meant to alter the picture.
- Report by the numbers above and by what changed in play.

## Parked

Flight recorder, screen census, 2D at 4:3 under widescreen, display-rate pacing as a patch, the stall log: they
treat symptoms. The modern C plan (2026-11-06) is folded into this one: names and types improve as code is
reworked, not as a pass of their own.
